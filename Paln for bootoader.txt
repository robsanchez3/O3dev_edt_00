  Plan de Bootloader USB

  Problema clave

  El código actualmente ocupa los 2MB completos de flash interna. Para añadir un bootloader hay que repartir ese espacio.

  ---
  Decisión 1 — Verificar si el STM32U599 tiene 4MB

  El ICF muestra 2MB, pero el STM32U599 puede tener 4MB (dos bancos de 2MB). Si es así, el problema desaparece:

  Bank 1: 0x08000000 – 0x081FFFFF (2MB) → Bootloader + Aplicación
  Bank 2: 0x08200000 – 0x083FFFFF (2MB) → Destino de actualización OTA

  Comprueba en el datasheet o CubeMX si el device es STM32U599NIH6Q con 4MB.

  ---
  Mapa de flash propuesto (asumiendo 4MB)

  0x08000000 – 0x0801FFFF  128 KB  Bootloader          (nuevo proyecto IAR)
  0x08020000 – 0x081FFFFF  1.875MB Aplicación actual   (desplazada 128KB)
  0x08200000 – 0x083FFFFF  2 MB    Staging area OTA    (Bank 2)

  Si solo hay 2MB internos, la staging area va en OSPI (ya hay 32MB libres).

  ---
  Flujo del bootloader

  Arranque → Bootloader (0x08000000)
  │
  ├─ Init mínimo (clocks, GPIO, OSPI para assets si se necesita LCD)
  │
  ├─ Espera USB (~2s, igual que configLoaderTask actual)
  │   │
  │   ├─ USB encontrado + "1:/Service/FW/firmware.bin" presente?
  │   │   ├─ Leer cabecera: magic + version + size + CRC32
  │   │   ├─ CRC OK? → Borrar staging area (Bank 2 o OSPI)
  │   │   │           → Copiar firmware.bin a staging
  │   │   │           → Verificar CRC de lo escrito
  │   │   │           → Escribir flag "update_ok" en RTC backup register
  │   │   │           → Reset
  │   │   └─ Segundo arranque: copiar staging → área aplicación → borrar flag → saltar
  │   │
  │   └─ No USB / no firmware.bin
  │       └─ Continuar al siguiente paso
  │
  ├─ Verificar validez de la aplicación
  │   (comprobar stack pointer y reset vector en 0x08020000)
  │
  ├─ Válida → Jump a aplicación
  │   └─ Deshabilitar IRQs, set VTOR = 0x08020000, jump a Reset_Handler
  │
  └─ No válida → LED error / pantalla error, espera USB indefinidamente
